Runtime contract draft: review notes
====================================

Base: stable-fixed 5d4b75e. This is a separate typing draft, not an addition to
any of the standalone compiler-repair PRs. Atom-result templates are retained.

The purpose is one checked function entry, reached by direct, indirect and
completed partial calls. Existing equations still determine answer order and
multiplicity. Declarations provide alternative membership evidence and do not
repeat the body. Reflection through get-type remains independent.

-------------

The mixed case uses the draft's explicit unanimity policy: only unanimous Atom
positions hold or quote. That policy and the separation of reflection from
enforcement are compatibility changes, not consequences of a generic theorem.

Only two example files are adapted relative to the fixed baseline:
- typed_partial_arguments: two expectations no longer duplicate answers/effects.
- types_dependent: derived classifications use explicit application guards.
These adaptations must accompany any upstream compatibility discussion.

Three execution traces
----------------------

1. (: inc (-> Number Number)), (= (inc $x) (+ $x 1))

   The public entry checks number(X), suspending on an open X; calls the equation
   worker; then checks number(Result). Its essential generated body is:

     (var(X) -> type_freeze(X, number(X)); number(X)),
     Worker(X, Result),
     (var(Result) -> type_freeze(Result, number(Result)); number(Result)).

   The worker is just +(X, 1, Result). No type query interprets the declaration
   at each scalar operation.

2. (: same (-> $a $a Bool)), (= (same $x $y) True)

   Entry creates one frame for the two inputs and their shared type witness.
   The worker returns true once. Exit retains unresolved correlated checks.
   Binding x to 1 then y to a string fails; binding both to numbers succeeds.
   A parameter is a shared existential membership witness, not a claim that
   the function is universally parametric.

3. (: old A), (: new A), (: edit (-> $a $a))

   If edit removes (: old A) and returns new, edit(old) still succeeds.
   The input retains its evidence from entry; the output is checked at return.
   A shortcut that merely rereads old's declarations after the body would
   reject this call incorrectly. Known structure is captured before the body;
   still-open leaves acquire evidence when bound. No full world is retained.

Implementation and limits
-------------------------

- types.pl: declarations, retained evidence, shared constraints and local guards.
- type_compilation.pl: entries, argument modes, code generation and refresh hooks.
- type_membership.pl: compiled membership with the general relation as fallback.
- type_obligations.pl: native attributed-variable evidence and notification.

Protected ListOf/TupleOf/PairOf structures over Number/String/Bool use local
delayed checks. A narrowly scoped self-call optimization reuses a checked
ListOf suffix obtained with cdr-atom. Other inputs/results remain checked;
contract edits retire the private entry. Arbitrary nominal families and shared
overloads do not gain these structural assumptions.

The four core files total 763 lines, including layout and invariant comments.
The optimizations are separate commits, so their generated-code
transformations can be reviewed independently.

Atom in a function slot is an evaluation convention. Inside a type, including
a constructor field, Atom is the type of every value, so (ListOf Atom) holds
every list; a declaration (: x Atom) is no type evidence. No signature
parameter stands for a type that mentions Atom, including through a nominal
index or inside a compound type. A regression checks both argument orders and
a constructor whose repeated indices must stay equal. A declared family has no
known variance: (List Atom) holds the lists built at index Atom, not a value
declared (List Number), and a value declared (List Atom) does not meet
(List $a). _ and %Undefined% stand for a whole slot only; inside a type, write
Atom for any value or a parameter for one shared proper type. The other mode
words are ordinary value-type names inside a type. Function types are compared
as written.

Unrestricted slots do not inspect cyclic host terms. Structural checks reject
cycles. Finite-tree proofs do not establish behavior on rational trees.

Collection follows native findall: unreturned local constraints disappear.
This does not decide inhabitation or prove that every discarded requirement
has a satisfying value. Spaces retain native assertion behavior rather than
serializing live constraint frames.

Measured costs
--------------

Fifteen interleaved repetitions, same declared workloads on both checkouts.
Microbenchmarks enter through compiled MeTTa calls, including stable's call-site
checks. Complete examples include loading. Times are median CPU seconds; the
draft was faster in each of the 15 paired nilbc runs.

Workload                         Stable inf.   Draft inf.    Stable s  Draft s
10,000 typed scalar calls             90,005       60,005    0.00256  0.00228
Typed counting, 200,000 steps      2,000,014    1,000,009    0.08774  0.01614
Typed constructor walk, 400        1,851,823       83,012    0.15939  0.00407
Typed open-variable loop              90,014       70,025    0.00359  0.00163
he_minimalmetta                   24,199,749   20,844,814    0.75495  0.66238
nilbc                             20,100,081   19,486,151    0.58260  0.53291

nilbc declares (: bc (-> $a Nat $b $b)) and recurses on open proof queries. Its
input evidence is retained, and an open input watched by an enclosing running
call is not watched again by each nested call, so nested calls on one open
value cost linear rather than quadratic time.

Changing bc's declaration to (: bc (-> $space Nat $query $answer)) removes
its shared input/result obligation. Earlier experiments with that weaker
contract were much cheaper, but matching the example answers is not a proof
of contract equivalence. Even an identical returned term can change its nominal
membership across declaration edits. The table retains the original shared
signature, and the example file is unchanged.

Ten untyped execution probes match inference counts exactly. The other complete
examples, holbenchmark, nars_tuffy and tilepuzzle, stay within 0.5% of stable's
inference counts. This does not claim zero load-time or mixed-dispatch
overhead. Whole-call residual validation can still rescan correlated open
nominal structures; the linear improvement applies to the protected fragment
above and to nested calls on one open input.

Mathematical correspondence and trust boundary
----------------------------------------------

These names refer to the generic MeTTapedia ConstraintTypes library:

Specification result                    Corresponding runtime obligation
DeclarationTyping.check_iff              type_member / type_evidence_has
OpenTyping.compile_correct               residual evidence and later bindings
CallTyping.frame_exact                   types_enter / types_exit
DeterminedMembership
  .compiled_membership_correct           type_code_goal, under its premises
UnsharedParameters.waive_joint_iff        singleton-slot omission, with coverage
RuntimeTyping.CanonicalTypes
  .waive_joint_iff_on_ground              coverage in models containing its facts
CheckCost.entry_check_covers_suffixes    reuse of protected ListOf suffix checks
CheckCost.incremental_exact              per-part structural checking
CheckingPatterns.matches_any             explicit Atom value checks only
Refresh.update_eq_fresh_compile          declaration dependency/refresh tracking

These are specifications and conditional laws, not a proof that the handwritten
Prolog predicates implement them. The native emitter, source interpretation,
SWI attributes, copying and database operations are outside that proof.
Canonical coverage is proved for ground finite atoms in the stated model; its
embedding into native membership remains an implementation obligation.
CheckingPolicy describes a separately labelled proposed wildcard/body policy.
It is not the selected Atom-template convention of this draft.

Validation
----------

113 runtime tests, 49 definition-order tests and 10 parser tests pass normally
and under -O. The example run passes 177 files / 786 assertions, with the
standard interactive exclusions; the network import example was exercised
separately. The watcher controls cover independent constraints after
discharge/copy, a later compatible witness/overload with one effect, and an
inner call's input bound inside or after that call.
Compiled and general membership, and contracts on ground values and on values
bound later, agree on 1,650 audited type/value pairs, including Atom inside
types, before and after declaration edits.

The source hashes remained unchanged during the benchmark. Passing these
checks establishes the recorded cases, not universal correctness or a promise
of production acceptance. The remaining performance and policy differences
above are part of the review, rather than hidden prerequisites.


Paper and incorporation
-----------------------

docs/runtime-types.pdf is the short mathematical note; its LaTeX source and
Makefile are alongside it. The note distinguishes specified judgments, generic
Lean laws and native implementation obligations. It makes no production or
full compiler-verification claim.

The latest pass has separate commits for a shared-witness correctness repair,
a semantics-preserving compiler/runtime source split, and this documentation.
The new type_compilation.pl is loaded by types.pl; existing src packaging
already includes it. No changes to the canonical fixed branches are required
to review or test this separate candidate.
